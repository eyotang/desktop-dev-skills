# 桌面端跨平台兼容

## 明确支持矩阵

- 列出目标系统版本、CPU 架构、框架版本、WebView/运行库、安装形态。沿用项目已有承诺，缺失时记录假设，不能把“支持 Ubuntu”扩展成所有 Linux 发行版。
- 对各项分别记录：计划、配置完成、编译通过、原生运行通过。单台开发机不能证明三平台兼容。
- 把共享业务逻辑与平台适配器分开。平台判断集中在能力边界，避免界面散落系统字符串判断；按实际能力处理不可用状态。

## 路径与文件系统

- 使用系统应用数据/缓存/配置目录 API。资源相对打包位置解析，不硬编码用户名、盘符、斜杠或当前工作目录。
- 覆盖带空格、中文、Unicode、只读目录及长路径；不假定文件系统大小写敏感，也不把所有路径转小写比较。
- Windows 保留文件名、文件占用、盘符/UNC 与 Unix 权限、符号链接语义不同。根据实际访问失败返回清楚错误，而非统一写成文件不存在。
- 需要原子保存时在目标文件同一文件系统创建临时文件，核对替换语义和已有目标处理。原子替换不等同断电持久性；别跨平台照搬 rename 假设。
- 导入/导出通过原生选择器和最小授权访问。配置引用外部文件时，重启后考虑路径失效和访问权限变化。

## 系统交互

- 验证平台菜单、Command/Control 快捷键、托盘、通知、外链和文件关联；功能不可用时给出明确降级，不模拟成功。
- 明确关闭最后窗口、托盘驻留和退出的差异。遵循产品选择和平台习惯，不隐式保留后台进程。
- 多显示器、DPI、Wayland/X11 与窗口位置恢复单独验证，不保证所有桌面环境可任意定位窗口。
- 使用参数数组启动必要的子进程，避免拼接 shell 命令；按架构提供 sidecar 并验证权限与退出回收。
- Ubuntu 无 Secret Service、无桌面会话或服务锁定时，应报告凭据无法保存，不回退文件。其余平台同样区分服务可用与用户授权。

## 运行时与网络

- Tauri 等系统 WebView 框架需在各目标系统检查 CSS、输入法、剪贴板、下载与资源加载；浏览器 Chromium 测试不能代替所有 WebView。
- 核对项目版本对应的系统依赖与最低运行环境。构建环境的动态库基线不能无意高于承诺的目标系统。
- 网络错误区分 DNS、代理、超时、TLS 与认证失败；保留证书/主机名校验，不为跨平台方便统一关闭校验。
- 系统代理和信任库是否被采用取决于实际客户端库；以真实配置验证，不只根据操作系统推断。

## 验证与交付

为修改涉及的功能建立矩阵，至少包含系统/版本、架构、执行的检查、结果和证据。优先在对应系统或合适的 CI runner 编译，运行测试仍需说明环境限制。

围绕路径、窗口、输入、原生插件及依赖开展有针对性的检查。未有设备的项标记未验证并提供复现步骤，不把生成 CI YAML 当作测试通过。
