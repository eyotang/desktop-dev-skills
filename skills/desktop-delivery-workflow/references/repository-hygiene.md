# 提交与公开仓库检查

在准备公开源码、用户要求去除组织信息或提交来源不清晰的文件时使用。仅在授权范围内读取；不为脱敏扫描读取系统凭据库。

## 确认对象

1. 确认仓库根目录、嵌套仓库、工作区变更、目标远端及已有历史。保留无关用户修改，不为清洁状态强制重置。
2. 检查仓库级提交身份；使用用户指定的公开身份或其已确认的 noreply 邮箱。不要猜测邮箱，也不要修改全局 Git 配置。
3. 区分新仓库首次提交与已有公开历史；不要为规避审查丢弃现有历史。

## 审查内容

- 检查源码、示例、文档、截图与元数据中的组织名称、邮箱、内部域名/IP、真实数据、个人绝对路径和秘密。使用虚构数据及保留示例域名；保留合法第三方许可证和必要署名。
- 本地研究、逆向证据、原始抓取、真实数据截图、临时参考副本、构建目录、依赖目录及嵌套独立仓库不默认进入交付。明确忽略规则并检查是否已被跟踪。
- `.gitignore` 只影响未跟踪文件的后续加入，不能清除已有跟踪内容或历史。
- 用明确文件列表暂存，检查 `git diff --cached`、暂存文件名和必要时的 `git show :<path>`。工作区已修正不代表暂存版本已修正。
- 检查结果优先记录路径和问题类别；不要把匹配到的密码、内部标识或完整数据回显到日志或报告。搜索模式无命中只代表该扫描范围内未发现，不保证绝对无泄露。

## 已有历史发现问题

普通修正提交不能去除历史中的敏感内容。列出受影响的分支、标签和已推送范围；历史重写与强制推送可能影响协作者，按明确授权和范围执行，不能顺便覆盖远端新增提交。已泄露凭据需要撤销或轮换，删文件或重写历史不能恢复其保密性。不要承诺能清除他人克隆或托管方所有缓存。

## 提交及远端核验

核对暂存范围、最终差异和作者身份后提交。推送前确认目标仓库及分支；远端有新提交时先检查并正常整合，不直接强推。完成后核对远端提交 ID、文件树及必要的历史范围。报告本次检查的范围与实际结果。
