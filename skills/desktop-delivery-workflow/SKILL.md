# 桌面开发到发布

## 先确定交付边界

读取项目约定、工作区改动、仓库根目录、分支、远端和目标平台。嵌套目录可能是独立仓库，不能在父仓库误提交它。确认任务要求停在修改、提交、推送、草稿还是公开发布；沿用会话已有授权，不重复询问。

按改动选择以下阶段。文档修正不必重新构建二进制；只做本地开发不必执行公开仓库审计和发布。已有开发、测试或发布规范时沿用，不创建重复流程。

## 开发：以实际证据收敛

- 用户要求参考已有应用时，先研究涉及的完整交互与状态，再修改；区分运行时观察、静态资料和推测。参考项目的本地副本可能过期，涉及发布方案时核对远端当前实现。
- 遵守用户指定的只读边界。研究真实应用或服务器不等于获准创建、修改或删除数据；写入验证使用隔离夹具。
- UI 问题先找布局约束与状态来源，避免不断叠加覆盖样式。检查最小窗口、长内容、拖动边界、滚动区域及实际可见面积。
- 验证用户可观察的行为；构建成功、浏览器模拟、原生运行、安装包运行分别记录，不能相互代替。
- 环境失败先与代码缺陷区分。资源不足时只清理已确认属于项目且可再生成的缓存，不删除用户数据或唯一交付物；无法验证的平台如实保留空缺。

## 提交：审查真正要公开的内容

执行 [提交与公开仓库检查](references/repository-hygiene.md)。只暂存本次任务文件，查看暂存差异和身份后提交。提交信息说明最终改动及目的，不包含内部背景或调试过程。

提交后核对提交作者、邮箱和文件树；需要推送时确认远端与分支，推送后核对远端提交。不能把本地提交完成报告为远端已更新。

## 发布：交付物必须对应源码

- 固定源码提交、版本、目标系统/架构及渠道。最后一次源码修改后重新构建受影响的交付物；旧安装包不能代表当前源代码。
- 平台签名、公证和更新包签名分别核验；签名材料不进入源码、普通配置或日志。新建或替换密钥按实际授权执行，已有密钥不得顺手覆盖。
- 先准备可审阅的源码、说明、构建流程和验证结果；只有缺少必要授权或信息时才请求补充，并说明具体受阻动作。
- 必需平台构建及检查完成后才发布。确认远端产物、校验和、更新清单和版本一致；工作流创建、上传开始或部分任务成功都不等于发布完成。
- 仅修改发布说明时保留已有正文，用文件传递完整文本并回读验证；不为文案重打标签或替换二进制。

## 交付记录

简要报告：改了什么、提交或版本、远端链接、实际验证及未验证项。若被权限或自动审批阻止，说明具体动作与返回原因，继续完成不依赖它的工作；不能把受阻步骤写成完成。

本技能可独立使用。需要更细的原生验证或签名规则时，可另行安装本合集的 `desktop-testing`、`desktop-release`；它们不是隐式依赖。
