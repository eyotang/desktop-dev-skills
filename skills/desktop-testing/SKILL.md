# 桌面应用测试验收

## 选择验证层级

先列出改动带来的用户可观察行为和失败边界，再选择能发现这些问题的最小测试组合。纯文案或低影响样式改动通常无需增加单元测试；涉及凭据、持久化、权限和迁移应覆盖失败路径。

| 层级 | 能证明 | 不能单独证明 |
| --- | --- | --- |
| 单元测试 | 业务规则、解析、状态转换 | 原生 API、系统权限 |
| IPC/契约测试 | 参数序列化、错误映射、边界校验 | 实际窗口和系统交互 |
| 浏览器 UI 测试 | 渲染、表单、交互流程 | 桌面 WebView、原生插件 |
| 原生集成/端到端 | 真实 IPC、窗口、系统服务 | 其他未执行平台的兼容性 |
| 安装包冒烟 | 安装后资源、权限及启动 | 所有升级与业务场景 |

## 安全且可重复的夹具

- 使用随机测试命名空间、临时目录和虚构数据，跟踪本次创建的资源并在结束时清理。不能扫描或重置用户真实钥匙串、数据库或主目录。
- 网络集成优先本地隔离服务或明确授权的测试服务。固定必要输入，不把真实服务密码塞入源码、命令行或快照。
- 故障注入覆盖服务不可用、拒绝授权、锁定、超时和写入失败；mock 只存在于测试路径，不能启用生产静默回退。
- 断言行为和状态转换，避免仅匹配实现函数调用或页面文案。测试日志只显示安全的状态和测试 ID。

## 桌面关键场景

- 校验 IPC 的无效输入、资源归属与并发修改；旧响应不能覆盖新选择，重复点击不能重复产生副作用。
- 覆盖窗口关闭/重开、进程退出、事件订阅释放、任务取消和后台工作是否仍存活。
- 对持久化流程执行重启后读取；凭据替换失败应保留旧值，删除失败不误报成功，旧秘密不得返回界面、IPC 响应或导出。
- 对原生选择器验证选择与取消；对路径覆盖空格、中文和无权限；对输入覆盖键盘操作、焦点恢复及输入法组合。
- 用户指定只读研究时，真实系统仅执行授权查询；增加、修改和删除验证使用隔离夹具，不能因测试需要扩大权限。
- 对布局问题检查父容器约束、固定高度、最小宽度、旧样式覆盖与占位元素；结合原生截图和可见区域几何关系验证，不仅检查 CSS 数值。
- 对 UI 改动检查最小窗口、高 DPI、长内容、空/加载/错误状态、浅深主题及无障碍关键路径。
- 从安装包检查资源加载和原生能力，不能只运行 dev server。

## 工具与平台

- 沿用项目现有测试工具。按框架版本查阅实际桌面自动化支持；不能假设同一 WebDriver 在三平台都可用。
- 浏览器环境显式 mock 原生适配器；测试报告标明模拟内容。浏览器 Playwright 通过不能标为 Tauri 原生端到端通过。
- 无自动化驱动的平台可用可复现的原生手工步骤或适用的系统自动化，记录实际证据，不伪造绿色测试。
- 跨平台矩阵记录系统版本、架构、运行库/框架、实际执行方式。没有执行权限或设备的条目标记未运行。
- 使用就绪条件和有界超时替代固定长等待；失败保留必要脱敏诊断。重试不能隐藏稳定失败，记录首次失败原因。

## 报告与停止条件

执行与改动相关的检查，通过且无新风险后停止重复测试。失败先判断实现、测试、环境哪个出了问题，修正后重跑受影响范围。

最终源码改动后重新生成受影响的安装包。区分当前源码、旧构建、最新 CI 产物和已发布产物；打包失败时不能把旧安装包当成已修复版本。

报告包含：场景、平台/构建、通过或失败、证据位置、模拟边界和未验证项。只配置了工作流、只编译通过、实际运行通过应分别描述。
