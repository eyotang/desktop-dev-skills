# Tauri 桌面应用开发

## 识别现有版本与边界

- 先读项目约定、Cargo.toml/Cargo.lock、前端清单/锁文件、Tauri 配置和 capabilities。沿用包管理器及架构，按锁定版本核对 API。
- Tauri 1 与 2 的权限和插件配置不可混用；迁移仅在任务要求时进行。新项目明确主版本并锁定依赖。
- 渲染层负责展示和交互，Rust 负责受信任的系统操作、业务校验及秘密使用。纯浏览器预览需显式模拟适配器，生产不得静默回退模拟数据。

## IPC 契约

- command 输入输出使用明确 DTO，统一字段命名、可空性和枚举表示；验证前后端序列化一致。
- 在 Rust 端校验路径、URL、对象归属、操作状态和数据大小。前端按钮禁用与 TypeScript 类型不能代替运行时校验。
- 定义稳定错误码和安全可展示消息；错误响应不能携带密码、令牌或原始含秘密的服务端诊断。
- 暴露业务操作而非通用系统执行器。不得为一个功能开放任意 shell、任意文件访问或任意系统凭据读取。
- 新秘密可由前端短暂提交，已保存秘密仅在原生端使用；不得提供返回旧明文的命令。持久化仅使用 Keychain、Windows 普通凭据或 Secret Service，失败不落普通文件。

## 权限与内容来源

- 对实际使用的窗口、WebView、插件命令和资源范围配置最小权限。核对当前版本中自定义 command 的注册与访问限制，不能假定它们自动被插件权限保护。
- CSP、资源协议范围、远程来源与外部链接分别处理；不要为解决开发报错把生产 CSP 或全部权限关闭。
- 外部 URL 先验证协议与目标，再用受控方式打开；不把非可信远程内容加载进拥有本地操作权限的窗口。
- 新增插件时同时检查 Rust 注册、前端依赖、能力配置和平台支持，避免只安装 npm 包就宣称集成成功。

## 异步与生命周期

- 阻塞 I/O、系统存储或 CPU 工作在合适执行器运行。不要持有普通互斥锁跨 await；线程敏感 API 遵循其调用要求。
- 长任务有稳定 ID、进度及终态。事件订阅及时解除；重复挂载、窗口重开不能积累监听器。
- 处理取消、超时、窗口关闭及退出。取消必须传到实际任务；对已有副作用说明结果，不能简单抛弃响应后声称回滚。
- 多窗口状态在可信后端协调；为同一资源的修改定义串行化或版本检查，避免过期响应覆盖新状态。
- 路径通过框架/系统目录 API 获取，不依赖启动工作目录。打包资源、用户数据、缓存和临时文件分开处理。

## 实现验证

1. 实现最小完整链路：界面输入 → IPC → 真实后端 → 明确结果。
2. 对修改范围运行类型检查、Rust 检查及相关测试；无需为纯样式改动扩大所有测试。
3. 验证参数无效、权限不足、后端失败、取消和重复操作，不只验证成功路径。
4. 在原生应用中验证使用的插件与窗口行为；发布构建验证资源路径和生产权限。

交付列明实际运行的命令、平台和未验证项。开发服务器可用不等于可分发应用可用。
