# 桌面端凭据安全存储

适用于需要可恢复秘密的桌面应用，例如服务连接密码、API Key、访问令牌、刷新令牌。Tauri/Electron 的渲染界面属于桌面应用，但凭据操作必须由可信原生进程完成。纯浏览器应用与 Web 后端不在本技能范围内。不要把此技能用于要求找回用户登录密码或替代登录认证中的密码哈希校验。

## 持久化位置：仅允许系统凭据存储

| 平台 | 唯一允许的持久化位置 |
| --- | --- |
| macOS | Keychain（钥匙串） |
| Windows | Credential Manager（凭据管理器）的 Windows 普通凭据 |
| Ubuntu | Secret Service，通常由 GNOME Keyring 提供 |

- 使用目标平台真实的安全存储 API 或明确启用对应后端的维护中库。依照项目实际依赖版本核实 API、平台特性和运行依赖，不照抄其他版本配置。
- 禁止把凭据存入 JSON/YAML/TOML/INI、`.env`、文本、SQLite/普通数据库、localStorage、sessionStorage、IndexedDB、应用设置、缓存、导出文件或代码仓库。
- 自行加密的普通文件仍不符合本约束，即使解密密钥放在钥匙串中也不允许。Base64、混淆、硬编码密钥、密码哈希均不能替代所要求的系统凭据存储。
- 系统凭据服务自身管理的数据库是允许的实现细节；禁止的是应用自行保存秘密的文件或数据库。
- 系统存储不可用、锁定或拒绝授权时，明确报告失败；不得退回文件、环境变量、浏览器存储或库的 mock/file backend。可提供明确标记的「仅本次使用」内存模式，不能显示为已保存。
- 非秘密配置可普通持久化：连接名称、服务器地址、用户名、凭据引用 ID 等。不得把带 userinfo、令牌查询参数或其他秘密的 URL 当作普通配置。

## 信任边界与凭据隔离

- 原生后端负责存取及使用秘密；前端只能提交新值、请求使用已保存凭据和查询非秘密状态。不得提供返回已保存明文的 IPC、HTTP 或调试接口。
- service 使用项目稳定的应用标识，例如 `com.example.product`；不要在所有产品中硬编码某个示例应用的标识。account/key 使用稳定、不含秘密的 profile ID；多账号环境加入正确的用户或租户归属隔离。
- 保存记录应绑定凭据对应的目标身份：规范化协议、主机、有效端口、认证账号，以及会影响保护等级的 TLS/StartTLS 设置。API 凭据还应绑定实际使用的服务/区域/作用域（按项目需要）。
- 使用前由后端重新验证绑定；前端的「已保存」状态只是提示，不能代替后端校验。修改服务器、账号或安全设置后，不能沿用旧密码发往新目标。跨主机重定向不能转发凭据。
- 原生接口限制到受信任窗口/调用者及允许的目标操作，不暴露任意系统凭据检索器。平台要求的用户授权由正常系统流程处理，不绕过。
- 系统存储 API 若阻塞或线程敏感，在适当工作线程调用；同一凭据的更新、读取使用和删除应串行或带版本保护，避免竞态覆盖。

## 更新界面：旧凭据不回显

1. 编辑连接时密码输入框为空；只显示「已设置」「未设置」或「存储不可用」等状态。
2. 不将旧秘密返回前端、回填输入框或 hidden 字段。不得先取回明文，再以 `type=password` 遮挡；遮挡不是不回显。
3. 不显示旧秘密的前后缀、长度、部分掩码或可恢复编码；不得提供查看/复制已保存秘密按钮。占位提示使用固定的非秘密文案。
4. 用户输入替换值时使用密码输入框，默认不明文展示。新值只能短暂存在于表单/必要请求内存中；不得进入全局持久化状态、开发工具记录或分析事件。
5. 明确区分「保持不变」「替换」「删除」。未输入新值默认保持不变；取消编辑也保持不变。清空输入框不能隐式删除，不能把占位符当成新密码。
6. 保存成功后清空表单中的新值，只返回状态。关闭/取消编辑也清空新输入。失败不能回填旧值或误报成功；保留用户新输入只限必要的当前交互内存。

建议契约，名称可按项目调整：

```ts
// 前端可见信息，不包含 secret 或可恢复秘密的字段。
type CredentialStatus = {
  configured: boolean;
  bindingMatches: boolean;
  availability: 'available' | 'locked' | 'unavailable';
};

type CredentialUpdate =
  | { action: 'keep' }
  | { action: 'replace'; newSecret: string }
  | { action: 'delete' };

// useSavedCredential 仅触发原生后端取出并使用，不返回明文。
// 更新响应只含 configured / operation status；不回送请求中的 newSecret。
```

`keep` 遇到目标身份不匹配必须要求新凭据或拒绝复用，不能隐式修改绑定。`replace` 的空值默认拒绝，不能用空字符串暗示删除。身份、绑定和权限校验在后端执行，不相信前端提交的状态。

## 保存、替换与删除的一致性

- 提供明确的保存选项；默认只在本次会话使用，用户选择记住后才持久化。
- 用于远程认证的密码优先在成功认证后保存；若产品明确提供「离线保存」，显示未验证状态，不声称认证成功。
- 替换失败保留原凭据；不要先删除旧值再尝试写新值。使用存储后端的替换语义，核实返回结果并避免竞态。
- 认证成功与保存成功分别处理。保存失败但连接成功时保留可用连接，并明确提示「本次可用，未保存」，不降级持久化。
- 「忘记密码」删除对应系统记录。移除连接时一并删除关联记录；删除失败不可丢弃唯一引用并声称彻底删除。处理好已不存在记录的幂等删除。
- 已选择保存的凭据取消记住后，应删除旧记录；若仍需用其完成本次连接，可先在后端读取并认证，再删除，但失败时需明确报告，不能静默保留并宣称已忘记。
- 删除持久化凭据不等于撤销远端令牌或断开现有会话；按用户请求和界面语义分别处理。

## 秘密生命周期与迁移

- 不把秘密放入命令行参数、URL、错误字符串、异常栈上下文、请求/响应日志、遥测、崩溃报告、调试输出、截图、剪贴板或测试快照。
- 禁止记录凭据请求体；诊断记录操作名和安全错误码，不拼接服务端可能携带秘密的原始诊断。
- 尽早释放秘密，原生可控内存使用可靠的清零机制；不声称 JavaScript 字符串能够保证物理擦除。密码保存成功、取消、会话结束时清理相应临时状态。
- 改造旧项目时，先找出现有存储及日志路径。迁移只在所需范围内读取旧凭据，不输出其内容；系统存储写入并确认后才移除旧秘密字段。失败则报告迁移未完成，不能破坏旧数据或声称已合规。
- 不创建包含旧秘密的普通备份。历史 Git、日志和备份中的泄露不能靠迁移消除；报告实际发现和必要的凭据轮换，不擅自删除历史或改动无关系统。

## 验证与交付

围绕实际实现验证下列边界，避免仅测试文案：

- 创建、重启后使用、替换、保持不变、忘记、取消记住、删除连接。
- 旧值始终不进入 UI、IPC 响应、状态持久化、导出或日志；提交新值的响应也不回送秘密。
- 目标、账号或 TLS 设置改变后无法复用旧凭据；同 DN/同用户名在不同配置中不串用。
- 存储锁定/缺失/拒绝、替换失败保留旧值、删除失败不误报成功、并发请求不过期覆盖。
- mock 仅用于测试，不可成为生产回退。原生存储联调用独立随机测试 ID、虚构秘密并在结束时删除，只操作测试创建的凭据，不读取真实用户凭据。
- 分别记录 macOS、Windows、Ubuntu 的实际验证；仅配置或编译过不能写成三平台实测完成。

交付说明保存位置、服务标识、更新/删除语义，以及尚未验证的平台；不得展示任何实际凭据。
