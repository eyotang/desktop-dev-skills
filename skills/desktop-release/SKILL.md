# 桌面应用打包发布

## 发布输入

- 读取版本、应用标识、已有发布流程、目标系统/架构及分发渠道；明确是本地交付、草稿发布还是公开发布，按已有授权执行。
- 检查工作区状态并记录实际源码提交和未提交变更。不能丢弃用户修改以得到“干净构建”；产物对应的源状态必须可追踪。
- 沿用已确定的 bundle identifier、升级标识和签名身份。改变这些可能影响数据目录、凭据访问、文件关联和升级识别。
- 使用锁文件和明确构建环境；先完成相关检查再构建安装包。不要把每个平台重新安装最新依赖当成复现策略。

## 平台产物

| 平台 | 按渠道选择的产物 | 必须区分 |
| --- | --- | --- |
| macOS | .app、DMG 或商店产物 | ad-hoc / 开发签名与正式分发签名；签名与公证 |
| Windows | MSI、NSIS 等安装器 | 可构建与签名可信；安装范围、架构与升级识别 |
| Ubuntu | deb、AppImage 等 | 发行版依赖、动态库基线、桌面集成与执行权限 |

- 不默认所有格式或 CPU 架构都必须生成，按项目承诺选择。通用 macOS 包需要所含架构的原生依赖与 sidecar 一致。
- macOS 按渠道核对签名、entitlements、公证及 stapling 要求；ad-hoc 验证成功不能写成已通过 Gatekeeper 分发验证。
- Windows 核对签名证书、时间戳与安装器升级行为；签名不保证 SmartScreen 信誉。不要通过禁用系统保护来证明安装成功。
- Ubuntu 检查在目标基线的安装与启动；不能仅在较新构建系统运行后声称旧系统兼容。

## 签名材料

- 使用平台凭据服务、受控签名服务或 CI 的秘密注入机制，遵循现有密钥管理方案。不能把证书私钥、密码或更新签名密钥提交到仓库、产物或日志。
- 应用运行时凭据与构建签名材料分开管理；本技能不改变应用仅使用系统凭据存储的规则。
- 缺少签名权限时完成可独立执行的构建及验证，准确标为未签名/未公证，不伪造成功或自动申请证书。

## 升级与恢复

- 自动更新需要验证产物签名及目标平台/架构，保护更新源。HTTPS 与更新签名各自承担不同保障，不互相替代。
- 验证旧版本升级、数据迁移失败、下载中断、签名无效及应用占用场景。失败时保留可运行版本和用户数据，不能静默清空配置。
- 制定版本回退与数据兼容策略；不能假定安装旧二进制能读取新数据。更新服务端清单前确认对应产物已可访问。
- 保留渠道隔离；测试版本不指向正式更新渠道。只有用户明确要求的发布范围才能修改。

## 最终验证与交付

从实际安装包完成安装、首次启动、核心原生功能、重启、升级及卸载相关检查；明确卸载是否保留用户数据。不要操作真实用户凭据或删除无关配置。

交付产物链接、版本、源码提交、系统/架构、校验和、签名/公证状态及已执行验证。无法运行的平台单独注明；CI 配置成功不等于产物已构建。

公开发布前先准备可审阅的产物与说明；若会话已有该范围的明确授权，继续执行，不重复索取许可。

## CI 与发布完整性

- 版本标签、应用配置及包清单保持一致；记录产物对应提交。参考其他项目时核对当前远端版本，不照搬旧本地副本中的渠道策略。
- 按支持承诺建立构建矩阵；依次执行检查、构建、验签、校验和、草稿上传和发布。必需任务失败时保留草稿，不发布缺包版本；除非用户已明确接受部分平台发布。
- 更新签名密钥按应用隔离，公钥可进入配置，私钥只经安全存储或受控 CI 注入；禁止日志回显。发现已有密钥先核对用途，不覆盖生成。更新签名不能替代 Apple 公证或 Windows 代码签名。
- CI 默认只读权限，发布任务才获得所需写权限；签名秘密只暴露给需要它的可信任务，不能注入不受信任的 PR 代码。
- 对实际产物验证签名与配置公钥匹配。更新清单只列出该更新器实际能安装且验签通过的平台包，不能把手动下载包全部加入自动更新清单。
- 发布重试优先继续同一草稿；不要随意覆盖已公开版本。串行化同一稳定渠道发布，防止旧版本覆盖最新版本；预发布与稳定渠道分离。
- 等全部必要任务结束后，回读公开 Release、产物及更新清单，核对版本、目标、URL 和校验和；上传成功不等于公开可用。

## 首次启动与说明更新

未签名或未公证的 macOS 包需明确标注实际状态。若分发方案需要提供隔离属性处理说明，限定为用户确认可信、核对校验和并已安装的那个应用，例如：

```bash
sudo xattr -dr com.apple.quarantine "/Applications/<App>.app"
```

替换为实际安装路径，并说明该操作移除该应用的下载隔离标记。不要使用清除所有扩展属性的宽泛命令或关闭全局 Gatekeeper；写入说明不代表获准在本机执行。正式签名或其他分发渠道不必复制此步骤。

发布说明的文案修正保留原有内容，使用文件或结构化参数传递正文，回读远端验证；不为文案重新构建、重打标签或替换已发布安装包。
