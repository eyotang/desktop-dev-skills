# 桌面端界面设计

## 先确定工作流

- 阅读现有界面与设计约束，识别用户最常做的任务、数据密度和主要对象；保留已依赖的快捷键与功能。
- 区分浏览、编辑、执行和设置场景。侧栏承载导航，工具栏承载当前上下文操作，详情区承载选中对象；不要为视觉效果强行采用三栏。
- 以真实的数据长度、空状态和错误状态设计；演示数据必须清楚标识，不能把模拟成功当作真实操作结果。
- 用户要求 Apple 风格时采用清晰层级、克制装饰和一致间距，同时保留 Windows/Ubuntu 的窗口与快捷键习惯。

## 窗口与布局

- 优先使用系统标题栏和窗口按钮。自绘标题栏时验证拖动区域、双击、缩放、系统菜单及按钮点击，避免可交互元素落入拖动区。
- 设定可用最小窗口尺寸；面板可以调整大小，尺寸有上下限。窄窗口下折叠次要面板，不能把主操作挤出窗口。
- 明确各区域滚动归属；工具栏与表头按任务需要固定，避免整页滚动导致导航消失。
- 长表格/树按数据规模分页或虚拟化；虚拟化后仍需正确管理焦点、选择和辅助技术语义。
- 窗口位置恢复时考虑显示器已断开、缩放改变，将窗口限制在可见工作区。

## 操作与反馈

- 区分选中对象、键盘焦点、正在编辑对象和执行目标；批量操作展示影响范围，不能只靠颜色表达。
- 所有关键操作可由键盘到达。遵循平台惯例使用 Command 或 Control，不覆盖常用系统快捷键；可见标签与实际快捷键一致。
- 菜单、树、表格和对话框按组件语义处理方向键、Enter、Escape、Tab。打开对话框移动焦点，关闭后恢复；危险操作不默认获得确认焦点。
- 异步操作显示进行中、成功、失败与可重试状态。取消按钮只有在实际取消任务时才写作取消；仅关闭界面不能暗示任务已停止。
- 编辑中的脏数据在切换对象、关闭窗口、退出应用时有一致的保存/放弃语义。避免每次普通导航都弹确认。
- 错误靠近操作发生处，保留可恢复上下文；不要用短暂 toast 承载必须处理的错误。

## 视觉与无障碍

- 用语义化颜色、字体、间距和圆角 token 支持浅色、深色、高对比度；优先跟随系统，允许产品需要的显式覆盖。
- 验证文字对比度、可见焦点、禁用状态和图标可访问名称。状态不能仅靠颜色，图标按钮不能仅靠悬浮提示解释。
- 适配系统字体、文本缩放、中文输入法、长译文及高 DPI。避免固定高度裁切文字；输入法组合期间不要误触发提交快捷键。
- 动效用于解释状态变化，遵循减少动态效果设置。模糊、透明与装饰不能降低可读性或拖慢大数据界面。

## 验证与交付

在实际桌面窗口中检查主要工作流、最小尺寸、长内容、双主题、纯键盘与屏幕阅读器关键路径。浏览器截图只能证明 Web 层视觉，不能证明系统菜单和窗口行为。

交付可运行界面或用户要求的设计产物，说明真实完成的交互、平台差异及未验证项。不要把静态设计标为功能完成。
